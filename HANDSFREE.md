# JARVIS Desktop 4.5.0 — локальный режим, голос, заметки, план и iPhone

Новая версия добавляет бесплатный локальный режим, выбираемый режим OpenAI, безопасную диагностику
распознавания и компактное рабочее пространство заметок. Жесты удалены по
просьбе владельца; камера и её компоненты не запускаются и не включаются в
новые сборки. Проверки исходников и проверка реального микрофона — разные этапы:
успешные записи и подставной API не подтверждают живое распознавание.

## Работа без платных API

В **Настройки → Работать локально, без платных API** включается сохраняемый
`free_mode`. Он запрещает облачные чат, распознавание и озвучку даже при
сохранённом ключе, старом выборе OpenAI и включённых облачных переменных
окружения. Источник ключа при этом не читается. Переход отменяет текущий ответ;
поздний результат старого запроса не показывается и не озвучивается. Чтобы снова
выбрать платный голос, владелец должен явно выключить бесплатный режим.
Сам переключатель не включает ранее запрещённые микрофон или локальный чат.

Для свободного разговора нужно отдельно включить **Локальный ИИ**: установленная
`qwen3:4b-instruct-2507-q4_K_M` работает через Ollama только на `127.0.0.1`.
Ожидание имени и основной русский режим используют Vosk; при включённом
двуязычном режиме установленный Whisper small/CTranslate2 работает на CPU.
Предпочтение языка интерфейса применяется только к неоднозначному определению
русского/английского, без ослабления проверок тишины и качества. Уверенно
распознанный английский сохраняется. Выбранный личный тембр продолжает работать
локально; готовое «Да, сэр» не ждёт загрузки нейросети.

Прогрев модели разговора получает отдельные 90 секунд; обычный вопрос сохраняет
предел 45 секунд и возможность отмены. Долгая подготовка голоса не блокирует
интерфейс, её ожидание ограничено 45 секундами. После неудачного фонового
запуска голоса действует пауза 60 секунд вместо повторного запуска при каждом
ответе. Английское приветствие готовится только по реальному запросу, а не
скрыто при каждом старте.

Локальные модели не расходуют токены платного API, но используют ресурсы
ноутбука. После загрузки моделей для разговора, речи, задач и заметок интернет
не нужен; сетевой музыкальный сервис требует собственного подключения.
Закрытый, спящий или выключенный ноутбук не принимает команды. Качество
небольшой локальной модели отличается от облачной, абсолютная безотказность
и мгновенный холодный старт не обещаются. Модель по-прежнему не разрешает
команды компьютеру: исходный запрос проверяет отдельный обработчик.

## Голос OpenAI

В **Настройки → Голос → OpenAI** включается единый режим: после локального
слова «Джарвис» фраза распознаётся через `gpt-transcribe`; свободный вопрос
обрабатывает `gpt-6.1-terra`; ответ поступает голосом Cedar через потоковый
`gpt-realtime-2.1-mini`. Последний озвучивает готовый текст, поэтому для этой
задачи используется экономичная модель. Полный `gpt-realtime-2.1` и Ash/Marin
можно выбрать переменными окружения ниже. Это штатные голоса ИИ, сходство с
актёром или персонажем фильма не обещается. Личные звуковые приветствия
остаются отдельными локальными записями.

Это последовательный голосовой маршрут, а не копия ChatGPT Voice: распознавание,
ответ и озвучка идут отдельными этапами. Ожидание имени остаётся локальным,
нет постоянно открытой платной сессии. Микрофон при озвучке подавляется для
защиты от собственных команд из динамиков; полноценное акустическое перебивание
не заявлено. Остановить ответ можно кнопкой Stop. Задержка зависит от сети,
провайдера и длины фразы; 300 мс не гарантируются.

При выборе OpenAI локальная Ollama не запускается и не прогревает модель заранее.
Ранее запущенные общие процессы не завершаются; явный локальный режим сохраняет
прежний прогрев. Только завершённый короткий отклик «Да, сэр» может кэшироваться
в ограниченной памяти, без хранения частных ответов и без повторного API-запроса.

Нужен приватно настроенный `OPENAI_API_KEY`. Без ключа, сети или бюджета режим
сообщает о недоступности; готовые команды, план и локальные заметки продолжают
работать, распознавание может использовать установленную локальную модель.
Текст модели никогда не разрешает команду компьютеру; выключение и перезапуск
по-прежнему требуют отдельного подтверждения владельца.

При смене движка уже включённый микрофон переходит на нужное распознавание:
приложение дожидается завершения старого сеанса и только потом запускает новый.
Выключенный владельцем микрофон не включается сам. Невалидная или ещё не
подготовленная модель OpenAI не подменяется неподтверждённым распознаванием.

Ошибка `credit_balance_exhausted` означает, что предоплаченный баланс API
OpenAI исчерпан. Создание нового ключа это не исправляет. Для реальной проверки
облачной речи нужны средства в [OpenAI Billing](https://platform.openai.com/settings/organization/billing).
Лимит расходов проекта и временное ограничение скорости — отдельные ошибки;
Jarvis показывает их раздельно. При отказе оплаченного API не запускается
цепочка повторных запросов. Локальные команды и данные продолжают работать.

Ключ создаётся через защищённый выбор проекта OpenAI Platform и подтверждение
точного локального env-файла. Ключ не передаётся в чат, Git, ярлык или журнал.
Для установленного приложения путь к **уже подтверждённому** env-файлу может
быть записан только в приватный `openai-key-source.json` профиля: поля
`version: 1`, `env_name: "OPENAI_API_KEY"`, `env_file: <абсолютный путь>`.
Автоматического поиска чужих `.env` или ключей Codex нет. Удаление этой записи
или файла отзывает подключение. В публичную сборку эта настройка не входит.

Дневная общая сумма резервов для чата, распознавания и озвучки по умолчанию
ограничена $0.25 и 100 запросами (UTC+5). Сначала резервируется верхняя оценка,
затем начинается запрос; неизвестный результат не возвращает резерв. Это
локальный предохранитель, не остаток счёта и не жёсткий лимит биллинга OpenAI.
Распознавание ограничено 12 секундами; длинную речь делите на несколько фраз.
Контекст истории и плана в облаке выключен до отдельного согласия.

Переменные окружения для разработчика (пример значений без секретов):

```dotenv
JARVIS_CLOUD_CHAT_ENABLED=0
JARVIS_CLOUD_STT_ENABLED=0
JARVIS_CLOUD_SPEECH_ENABLED=0
JARVIS_CLOUD_CHAT_MODEL=gpt-6.1-terra
JARVIS_CLOUD_SPEECH_MODEL=gpt-realtime-2.1-mini
JARVIS_CLOUD_SPEECH_VOICE=cedar
JARVIS_CLOUD_DAILY_BUDGET_USD=0.25
JARVIS_CLOUD_DAILY_REQUEST_LIMIT=100
JARVIS_CLOUD_HISTORY_ENABLED=0
JARVIS_CLOUD_PLAN_CONTEXT_ENABLED=0
```

Выбор OpenAI в интерфейсе включает три канала для текущего владельца; флаги
позволяют включить их раздельно при разработке. Отключение режима отзывает его
разрешение; явно включённые отдельные env-флаги сохраняют свой смысл.

Документация API: [Realtime](https://developers.openai.com/api/docs/guides/realtime-conversations),
[модель озвучки](https://developers.openai.com/api/docs/models/gpt-realtime-2.1-mini),
[распознавание](https://developers.openai.com/api/docs/guides/speech-to-text).

## Проверка владельца

Windows Hello опционален. В разделе **Управление** можно включить защиту и
нажать **Подтвердить через Windows Hello**. Windows сама предложит доступный
способ: лицо, отпечаток или PIN. Проверка подтверждает текущего пользователя
Windows, а не личность говорящего. Разрешение живёт пять минут в памяти и
сбрасывается при блокировке, отключении сеанса и завершении Jarvis; фото и
биометрические шаблоны не читаются. Режима жестов и переключателя камеры нет.

## Мои приложения и проекты

В **Управление → Проекты** добавьте нужную папку и нажмите **Найти проекты**.
Поиск ограничен двумя уровнями, 4000 записями каталогов и 200 проектами; он читает
имена и признаки проекта, не запускает его код. Поддерживаются также `.idea`,
`pom.xml`, `build.gradle` и другие обычные признаки проектов IntelliJ/PyCharm.
Для конкретного проекта выберите PyCharm, IntelliJ IDEA, VS Code или Проводник.
Можно добавить проект вручную внутри разрешённой папки.

Команды: **«открой проект Jarvis»**, **«можешь открыть проект Альфа?»**,
**«open project Research and Development»**. Слова внутри сохранённого имени
не удаляются как обращение или вежливость. При совпадении имён голос просит
уточнение; кнопка открывает именно выбранную запись. Можно менять отображаемое
имя и дополнительные имена для команд, включая очистку списка. Файлы и папки
при этом не переименовываются и не удаляются.

В **Мои приложения** подтвердите владельца через Windows Hello, выберите обычный
Windows EXE и дайте ему имя. Команда **«открой приложение Редактор»** запускает
ровно подтверждённый файл без добавленных аргументов. Оболочки и интерпретаторы
не добавляются как приложения. После обновления EXE нажмите отдельную кнопку
повторного подтверждения: изменившийся файл автоматически не одобряется.
Отзыв доступа во время проверки файла или редактора отменяет запуск.

Разрешения хранятся только в личных `catalog.db` (схема 3) и `app_catalog.db`
(схема 2) рядом с `desktop.db`. Новые счётчики сохраняют уникальность записей
после удаления, чтобы старая кнопка не открыла другую программу. Миграции
добавляют служебные таблицы и сохраняют существующие имена, пути и разрешения.
Перед обновлением сохраните совместимые копии этих баз вместе с основным
профилем; более старая версия каталогов откажется открывать новую схему.

## Обычный запуск

После сборки и приёмки 4.5.0 откройте `JARVIS.lnk` из
`Downloads/Jarvis-Desktop-4.5.0` или **JARVIS Desktop** в меню «Пуск».
Новый каталог установки — `%USERPROFILE%\Applications\JarvisDesktopLocal-4.5.0`.
На момент подготовки этой инструкции последней проверенной установкой остаётся
4.4.0; создание новых файлов сборки само по себе не обновляет её ярлыки и автозапуск.
При закрытии окна помощник остаётся в трее; полное завершение — в меню значка или кнопкой «Завершить Jarvis» в настройках.

Автоматическое ожидание и запуск при входе в Windows включаются двумя отдельными
переключателями. В личном профиле они включены по запросу владельца.
Микрофон и его состояние видны в интерфейсе. Кнопка микрофона и меню трея
останавливают запись немедленно. Автоматическое ожидание можно отключить
в настройках. Приложение не включает выключенный ноутбук и не пробуждает его из сна.

Скажите **«Джарвис»**, дождитесь **«Да, сэр»**, затем команду. Можно произнести
имя и команду вместе. Пока помощник озвучивает ответ, микрофон защищён от
самопрослушивания; для следующей голосовой команды дождитесь окончания речи.
Текстовый ввод работает отдельно, включая прерывание старой озвучки.

## Голос и два языка

Режим «Базовый голос» явно обозначает Piper/Windows. Для голоса из
предоставленной записи выбирается «Голос по вашему образцу». Если он ещё не
готов, другой тембр не включается незаметно. В звуке модели может сохраняться
фон; проверенная очистка не дала устойчивого улучшения, исходный тембр сохранён.

В личном режиме голос по предоставленному русскому образцу использует XTTSv2
в отдельном локальном процессе. Короткое «Да, сэр» — готовая запись пользователя:
оно доступно во время подготовки модели. Новая фраза озвучивается постепенно,
с первого звукового фрагмента. Модель разговора остаётся прежней локальной
Qwen3 4B Instruct; смена голоса не требует увеличивать её до 13B.

В прежних измерениях до приёмки 4.4.1 холодная подготовка голосовой модели
занимала примерно 18–35 секунд на проверенном ноутбуке. Прогретый первый
звуковой фрагмент измерен около
0,3–0,36 секунды. Это отдельный этап, не полный путь от микрофона до динамика.
В режиме по образцу другой тембр автоматически не подставляется. Пока модель
готовится, фиксированный отклик доступен сразу, а основной ответ виден текстом;
ответ сохраняется в ограниченной очереди памяти до готовности голоса
(не более 45 секунд), а новый запрос, выключение речи и смена настроек
отменяют устаревшую озвучку. Короткое «Да, сэр» не удаляет ожидающий ответ;
старый ответ не начинает звучать поверх окна ожидания новой команды. При отказе
показывается явное состояние. Базовый Piper и отдельные Евгений/Айдар выбираются
самостоятельно; фактический источник показан в настройках.
Отсутствие модели или GPU не ломает текст, план и команды.
Принятый личный тембр в 4.4.1 не заменялся. Синтез явно читает
`repetition_penalty` из закреплённой официальной конфигурации XTTS (5 вместо
неявного значения 10 метода синтеза). Это исправление параметра, а не доказательство
естественной интонации: человеческая оценка просодии ещё не проведена.

Для русского и английского распознавания используется Whisper-small на CPU,
с локальным определением речи. Простые точные команды сохраняют быстрый путь
Vosk. Сложная свободная фраза дополнительно распознаётся после проверенного
слова вызова; этот этап на CPU может занимать около двух секунд.
По умолчанию аудио хранится только в ограниченных буферах памяти, не сохраняется
и не отправляется в интернет. Отдельно разрешённое облачное распознавание описано
ниже; оно получает лишь короткую команду после проверенного вызова.
Обычный запуск не скачивает модели.

Детектор речи проверяет наличие голоса, сохраняя начало всей ограниченной фразы.
После ошибки можно повторить команду в оставшееся окно ожидания; истёкшее окно
не возобновляется от постороннего уведомления. Непроверенное распознавание Vosk
не обходит второй распознаватель только из-за совпадения с названием команды.
В 4.4.1 отклик «Да, сэр» не сбрасывает уже принятую команду. Начало ограниченного
аудиофрагмента сохраняется независимо от промежуточного текста Vosk; после
точного вызова второй распознаватель может восстановить фразу, даже если Vosk
вернул только имя. Проверки с реальными локальными моделями и синтетическим PCM
подтверждают передачу фрагмента, но не заменяют речь пользователя в комнате.

«Включи Яндекс.Музыку», «можешь открыть Яндекс Музыку» и «открой гугл хром»
обрабатываются локально. Названный Chrome запускается из стандартной установки
после проверки подписи Google; другое приложение вместо него не подставляется.
Открытие плеера не означает, что музыка уже играет. Вопрос «что ты умеешь»
получает справку о реальных функциях без обращения к разговорной модели.

Точные короткие вопросы «как дела» и «что ты умеешь» с подтверждёнными словами
Vosk не отправляются повторно в тяжёлое распознавание. При неуверенном результате
помощник просит повторить голосом не чаще одного раза за исходное окно вызова.
Это не продлевает разрешение команды. После короткой защиты от эха интерфейс
снова показывает «Слушаю команду…»; акустическое качество на конкретном микрофоне
проверяется отдельно. Ответы на текстовые команды и фиксированные сообщения об
ошибках также озвучиваются выбранным голосом, если речь включена.

Фраза **«Jarvis, wake up, daddy’s home»** включает личную запись приветствия
с музыкой. Запись воспроизводится целиком, отдельно от синтеза; это приветствие,
а не сообщение о выполненных настройках компьютера. В личной установке файл
и проверяющий его контрольную сумму манифест находятся в
`%USERPROFILE%\JarvisData\VoiceLab\audio-cues.json` и рядом с ним.
В репозитории и публичной сборке записи нет; при её отсутствии Jarvis произносит
«Добро пожаловать домой, сэр» выбранным голосом. Пауза речи и новый запрос
останавливают воспроизведение. Английский вызов проверяется отдельно от
обычного русского «Джарвис»; качество собственного микрофона не заменяется
проверкой синтетического образца.

Для вызова английским произношением имени добавлена небольшая отдельная модель
Vosk English. Она используется только при включённых двух языках и выдаёт лишь
кандидата вызова; точное первое слово Jarvis затем проверяется по исходному
аудио. Обычная фоновая речь без кандидата не запускает Whisper. Русский вызов
имеет приоритет, одна фраза не распознаётся и не выполняется дважды.
Отмена и смена настроек сбрасывают незавершённую фразу. Дополнительная память
модели в отдельной проверке составила около 115 MiB; это не измерение всей программы.

Модель установлена отдельно для личной версии. Для новой установки разработчиком:

```powershell
python -m desktop.english_wake --install-model
```

Загружается официальный `vosk-model-small-en-us-0.15` с сохранением лицензии
Apache 2.0 и проверкой архива и 14 файлов по SHA-256. При обычном запуске загрузок
нет; отсутствие английской модели не отключает русский вызов и текстовые команды.

В настройках доступны темп, резервный голос и два языка. Качество сходства
с образцом и работа с вашим микрофоном требуют личной проверки на слух:
автоматическая расшифровка не доказывает идентичность голоса.

XTTSv2 и личные Silero-веса имеют ограничения некоммерческого использования.
Они и предоставленные записи не входят в публичный установщик/репозиторий.

## Текущий план

Страница **План** содержит сегодня, завтра и выбранную дату. Можно добавить
цель, задать необязательное время, перенести одно дело, пропустить отдельную
тренировку и изменить недельные дни. Сохранение применяется к будущим
уведомлениям сразу; уже поставленная в очередь озвучка перепроверяет план.

В личном профиле владелец подтвердил **вторник, четверг, воскресенье, время гибкое**.
На среду тренировка не создаётся. Время тренировки не выдумывается; при гибком
времени нет навязанного часового уведомления «пора идти».

Примеры:

- «Я хожу в зал во вт чт вс» — меняет недельное правило.
- «Я хожу в зал во вт чт вс в 18:00» — добавляет выбранное время.
- «План на сегодня», «что у меня завтра», «расписание» — текущие локальные дела.
- «Добавь цель на завтра прочитать главу» — датированная цель.
- «Я сходил в зал» — собственный отчёт о выполнении за текущий день.
- «Учился 40 минут» — собственный отчёт о времени, не независимое доказательство.
- «Следующий шаг» — сначала актуальный план, затем очередь задач.

Статусы **выполнено**, **пропущено** и **не подтверждено** различаются.
Отсутствие отчёта не означает провал. Время таймера, активное приложение и
ответ ИИ не меняют статус выполнения.

Утренний обзор звучит один раз за местный день при запуске или первом
действительном обращении с 05:00 до 12:00. Одно слово вызова даёт короткий
отклик; после первой команды может следовать обзор. Ночью приложение не
выдумывает утреннее пробуждение по таймеру.
Вечернее предложение спланировать завтра установлено на **22:00, UTC+5**,
с ограниченным часовым окном догоняющего уведомления. Пауза и «Не беспокоить»
доступны в настройках. Повторный запуск не дублирует дневное обращение.
Для своевременных сообщений приложение должно работать в окне или трее.

Отдельная явная команда **«Доброе утро»** запускает личное приветствие.
Только подтверждённое полное воспроизведение записи, включая завершение вывода
звука, разрешает одно продолжение: открыть Яндекс Музыку и попытаться возобновить
её музыкальный сеанс. Новый запрос, «Стоп», выключение речи, отзыв доступа или
закрытие отменяют продолжение. Отсутствующая запись и голосовой текст вместо неё
не считаются завершённой записью. Это отдельный сценарий от дневного обзора плана.

Историческая копия облачных данных от **10 октября 2026** остаётся отдельным
источником только для чтения. «Старое расписание»/«расписание из копии» и
**Мои данные** явно указывают дату. Она не задаёт актуальные дни зала.
Более поздние облачные записи и свежая синхронизация LMS не считаются восстановленными.

## Наблюдения и личный контекст

Наблюдение за активностью — отдельный переключатель. Сохраняются только
минутные суммы категорий: рабочие приложения, игры, медиаплееры, бездействие,
неизвестно. Имя текущего процесса используется для классификации и отбрасывается.
Заголовки окон, адреса, клавиатура, скриншоты и полный список процессов не собираются.
Разрывы, сон и остановка приложения не засчитываются как работа.

Категории хранятся семь дней, не входят в постоянные резервные копии и удаляются
кнопкой. Браузер остаётся неизвестным; работа редактора не доказывает учёбу.
Посещение спортзала компьютер не подтверждает. Подсказки помогают разбираться
в дне, а отчёт о результате остаётся за пользователем.

Локальному ИИ можно отдельно разрешить ограниченную проекцию текущего плана
и этих суммарных подсказок. Она передаётся только для вопроса о личном плане
или его продолжения. Заметки, архив, файлы, секреты и права управления в неё
не входят. Изменение плана через интерфейс или точную команду сохраняется
отдельным обработчиком; модель не получает инструментов записи.

## Расход токенов

Основной локальный ИИ обращается только к `127.0.0.1:11434`, без облачного
провайдера. Обычные команды, планы, задачи, таймеры, наблюдения и напоминания
дают **ноль запросов к языковой модели**. Свободный вопрос вызывает один запрос,
без автоматической цепочки извлечений/повторов. Режим размышлений выключен.

Обычный ответ ограничен 256 выходными токенами; явно подробный запрос — 768.
История сокращается первой, исходный вопрос не обрезается. Символьный бюджет
не выдаётся за точный токенизатор. В настройках показываются фактические
входные/выходные счётчики Ollama, ошибки и время ответа; отсутствующий счётчик
обозначается неизвестным, а не нулём. В статистике не сохраняются тексты.
Достигнутый лимит не запускает повторный запрос и не выдаёт обрывок за полный ответ.

Ожидание разговорной модели не занимает очередь команд компьютера. Пока ответ
готовится, можно ввести следующую команду или нажать **Стоп**. Голосовое «стоп»
принимается после проверенного вызова или в действующем окне ожидания команды.
Отмена прерывает запрос и озвучку, удаляет незавершённый текст и не превращает
его в историю или действие. Одновременно выполняется один разговорный запрос;
новая свободная реплика заменяет единственную ожидающую. Команды выполняются
последовательно; уже переданное системе действие отмена не откатывает.

## Необязательный облачный режим

`desktop/cloud_ai.py` и `desktop/ai_routing.py` содержат ограниченные адаптеры
OpenAI. Все облачные режимы выключены по умолчанию. Ключ передаётся через
окружение процесса после отдельной настройки; адаптеры не ищут его в заметках
и самостоятельно не читают env-файлы. Для этого выпуска реальный ключ, платный запрос, баланс и
готовность сквозного облачного пути ещё не подтверждены.

| Переменная | Назначение и значение по умолчанию |
| --- | --- |
| `OPENAI_API_KEY` | Секрет окружения; сам по себе ничего не включает |
| `JARVIS_CLOUD_CHAT_ENABLED` | `1` явно включает облачные свободные вопросы; по умолчанию выключено |
| `JARVIS_CLOUD_STT_ENABLED` | `1` отдельно включает облачное распознавание команды; по умолчанию выключено |
| `JARVIS_CLOUD_HISTORY_ENABLED` | `1` отдельно разрешает ограниченную историю в облаке; по умолчанию выключено |
| `JARVIS_CLOUD_PLAN_CONTEXT_ENABLED` | `1` отдельно разрешает ограниченный контекст плана в облаке; по умолчанию выключено |
| `JARVIS_CLOUD_CHAT_MODEL` | `gpt-6.1-terra`; также поддержан `gpt-6-luna`, другие имена отклоняются |
| `JARVIS_CLOUD_DAILY_BUDGET_USD` | Локальный суточный резерв, по умолчанию `0.25`, максимум `10` |
| `JARVIS_CLOUD_DAILY_REQUEST_LIMIT` | Общий суточный предел попыток чата и распознавания, по умолчанию `100`, максимум `100` |

День лимита считается по UTC+5. Сумма резервируется до отправки; при неизвестном
исходе резерв сохраняется. Это локальный ограничитель данного приложения,
не подтверждённый баланс и не жёсткий лимит счёта OpenAI. Другие приложения
и запросы с тем же ключом им не ограничиваются.

Облачный чат принимает вопрос до 8000 символов и до 512 выходных токенов,
без инструментов, с `store=false`. История и план требуют собственных флагов
даже при включённом локальном контексте; заметки не прикладываются автоматически.
Ограничение `store=false` не является обещанием нулевого хранения у провайдера.
Отмена завершает текущий запрос и не переключает его на другую модель.
При недоступности облака допускается одна попытка явно включённого локального
чата, без повторной отправки в облако.

Вызов имени остаётся локальным. После подтверждённого вызова облачный STT может
получить командный фрагмент не длиннее 12 секунд, mono PCM16le 8–48 kHz,
в виде WAV из памяти. Фоновый микрофон и непроверенный кандидат имени в облако
не отправляются; Jarvis не сохраняет этот WAV. Одна отправка ограничена пятью
секундами; при недоступности допускается одна локальная попытка распознавания.
Результат остаётся текстом для обычной проверки намерения, не полномочием на ПК.

## Заметки Obsidian

В разделе **Заметки** можно явно выбрать локальное хранилище Obsidian, создать
новую Markdown-заметку, найти и посмотреть существующие, открыть выбранную
заметку или хранилище. При включённой проверке владельца выбор и действия
требуют действующего доступа. Выбор папки не устанавливает Obsidian.
Существующие файлы не перезаписываются; новый текст ограничен 20 000 символов.
Список и поиск ограничены, предпросмотр показывает до 2000 символов как обычный
текст: Markdown/HTML и инструкции в заметке не выполняются.

«Заметки обсидиан» показывает ограниченный список; «мои заметки» и
«найди заметку …» учитывают также прежние SQLite-заметки. Они остаются
доступны отдельно. При настроенном хранилище «запомни …» создаёт новую заметку
в нём; без хранилища сохраняется прежний локальный путь. Заметки автоматически
не отправляются ИИ и не становятся командами управления.

## Музыка и действия Windows

«Открой Яндекс Музыку» предпочитает проверенное установленное приложение.
«Включи музыку» продолжает только распознанный музыкальный сеанс Windows,
отдельно проверяя состояние воспроизведения. Команда не нажимает слепой
Play/Pause и не включает видео вместо музыки. При холодном запуске есть
ограниченное ожидание регистрации плеера. Неудача не сообщается как успех.

Для первого входа/Play и выбора утренней подборки может потребоваться действие
в самом плеере. «Утренняя музыка» пытается продолжить только сеанс Яндекс Музыки;
если воспроизведение не подтверждено, сообщает об этом и предлагает Play вручную.
Холодный запуск случайного трека или «Моей волны» не подтверждён: во время
проверки нативное окно плеера отсутствовало, адресный элемент управления не найден.
Недокументированные URL, слепые клавиши и выдуманный выбор подборки не используются.
Изменившийся исполняемый файл после автообновления требует обновить проверенные
установочные метаданные. В резервном случае открывается известный сайт сервиса.

Питание, перезапуск, блокировка и гибернация требуют отдельного одноразового
подтверждения в приложении. Выключение/перезапуск используют отменяемую задержку
без принудительного закрытия документов. Голос, модель и импортированные записи
не подтверждают питание. Реальное выключение ноутбука не используется в тестах.

## iPhone: защищённое подключение

Компаньон — мобильная веб-страница: сегодня/завтра, добавление дел, отчёт о
выполнении, дни зала и отдельно разрешённые команды ноутбука. Это тот же локальный план. Установка в Safari на экран
«Домой» поддерживается. Личные данные не кэшируются для офлайн-показа.

Сервер по умолчанию выключен и всегда слушает только `127.0.0.1:8767`.
Он не открывает порт всем сетям и не меняет брандмауэр. На iPhone понадобится
однократная настройка личного HTTPS-соединения; физическое устройство в
автоматических тестах не подключалось.

В **Управление → Подключить iPhone из любой сети** есть пошаговая настройка
Tailscale. Нажмите проверку состояния. Если клиент отсутствует, отдельная кнопка
скачивает официальный установщик и проверяет подпись Tailscale; другая кнопка
передаёт его Windows. Jarvis не входит в аккаунт, не подтверждает системные
диалоги и не устанавливает приложение на iPhone за вас. Войдите на обоих
устройствах в одну личную сеть. Для этого не нужен собственный облачный сервер.

Включите защиту владельца, подтвердите Windows Hello, затем нажмите
**Настроить частный HTTPS**. Jarvis проверяет занятость маршрута и вызывает
только следующий частный Serve; публичный Funnel и замена чужой настройки запрещены:

```text
tailscale serve --bg --https=443 http://127.0.0.1:8767
```

Вне Git, в `%USERPROFILE%\JarvisData\Desktop\phone.env`, уже создаётся случайный
ключ плана, отдельный ключ управления и выключенные флаги. Старый файл
дополняется недостающими полями атомарно; существующие ключи не меняются.
Ошибочный, связанный или неоднозначный файл отклоняется без перезаписи.
Настройка в приложении сохраняет только подтверждённый `https://*.ts.net`
origin без пути/порта, включает флаги и перезапускает собственный локальный мост.
Нажмите **Разрешить удалённое управление** отдельно; готовый HTTPS сам
по себе не выдаёт это разрешение.

Скопируйте ссылку плана отдельной кнопкой при действующем Windows Hello.
Откройте её в Safari на iPhone через Tailscale. Ключ плана передаётся во
фрагменте `#token=КЛЮЧ`, который немедленно удаляется из адреса.
Отдельный ключ управления копируется другой кнопкой и вводится вручную на
iPhone; из URL он не принимается. Оба ключа хранятся только в сессии вкладки,
не в постоянном кэше. Не отправляйте их посторонним и не добавляйте `phone.env` в Git.

Удалённый доступ предлагает конечный список команд и имена уже разрешённых
проектов/приложений; пути файлов, оболочка, произвольные аргументы и результаты
ИИ не принимаются. Опасные действия требуют отдельной кнопки с одноразовым
подтверждением на 60 секунд. Перезапуск Jarvis, отмена, смена ключа и повтор
запроса не восстанавливают это подтверждение. Неизвестный исход не повторяется
автоматически; сначала проверьте ноутбук. Подтверждение обработчиком не доказывает,
что окно открылось на разблокированном экране или музыка действительно слышна.

Разрешение сопряжённого телефона сохраняется между запусками и не зависит от
истечения пятиминутной локальной проверки Hello. **Отозвать разрешение**
немедленно блокирует следующие команды; завершение Jarvis прекращает приём
запросов и ждёт уже принятые операции перед закрытием данных. Камера и Hello
по-прежнему сбрасываются каждый сеанс. Вручную включайте только собственный телефон.

| Переменная личного `phone.env` | Назначение |
| --- | --- |
| `JARVIS_PHONE_ENABLED=0` | По умолчанию мост выключен; настройка меняет на 1 |
| `JARVIS_PHONE_TOKEN` | Случайный ключ плана, создаётся локально |
| `JARVIS_PHONE_ORIGIN` | Точный HTTPS-origin личного маршрута |
| `JARVIS_REMOTE_ENABLED=0` | Отдельный флаг команд; настройка меняет на 1 |
| `JARVIS_REMOTE_TOKEN` | Другой случайный ключ, не совпадает с ключом плана |

Секреты из внешнего окружения имеют приоритет при запуске. После ручной ротации
ключей перезапустите Jarvis и подключите вкладку заново. Старый работающий мост
отклоняет запросы при изменении своего ключа, origin или флага. HTTPS-подключение,
вход и настоящее получение команды физическим iPhone остаются отдельной ручной приёмкой.

Каждый запрос требует Bearer, проверенного Origin и ограниченного JSON.
Повтор записи защищён сохранённым ключом идемпотентности. Неопределённый исход
после аварии даёт 409: сначала проверьте план, затем создайте новый запрос.
API плана не вызывает PC-команды или ИИ. Отдельный API управления требует
обоих ключей и выданного разрешения, передавая только разрешённые идентификаторы
детерминированному обработчику. Ответы модели не участвуют в авторизации.
Без настроенного транспорта статус остаётся «не подключено», а не обещанием
работы телефона. На iPhone голосовой запуск можно связать с личной командой Siri;
замена системного слова активации iOS этим приложением не заявляется.

## Необязательные уведомления и звонки

Весь внешний канал по умолчанию выключен. Секреты задаются только окружением
или тем же частным `phone.env`; основной помощник не зависит от них.

| Канал | Переменные |
| --- | --- |
| Telegram владельца | `DESKTOP_TELEGRAM_ENABLED=1`, `DESKTOP_TELEGRAM_BOT_TOKEN`, `DESKTOP_TELEGRAM_CHAT_ID` |
| Необязательный звонок владельцу | `JARVIS_PHONE_CALLS_ENABLED=1`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`, `TWILIO_TO` |
| Личная фиксированная аудиозапись в звонке | `TWILIO_PERSONAL_AUDIO_URL` — разрешённый HTTPS-адрес, заданный владельцем |

Ключей/подключённого провайдера в этой установке нет: настоящие звонки и push
не считаются работающими. Платные аккаунты и звонки не создавались.
Телефонный голос провайдера — отдельный резерв, не клон Jarvis. `<Play>`
проигрывает настроенную фиксированную запись и не означает динамическую озвучку.

Только вечернее событие может запросить звонок при явном флаге и валидной
конфигурации: не более одной попытки в день, с 08:00 до 22:30 местного времени.
Устаревший план перепроверяется перед отправкой. Неопределённый исход HTTP
не повторяется автоматически; подтверждённый rate limit имеет ограниченный
повтор. Чужие номера и адреса из текста/ответа модели не принимаются.

## Хранение и проверка установки

Новые данные: `%USERPROFILE%\JarvisData\Desktop\desktop.db`, схема **3**.
Схемы 1/2 обновляются без сброса, перед обновлением создаётся online-backup.
Дополнительные личные базы: `catalog.db` — схема 3, `app_catalog.db` — схема 2,
`phone.sqlite3` — идемпотентность запросов, `remote_control.sqlite3` — хеши
одноразовых подтверждений. Последние две создаются только при использовании
соответствующего канала; сырые ключи и команды подтверждения в них не сохраняются.
При использовании облачного адаптера `cloud-ai.sqlite3` хранит только локальные
суточные резервы и числовые итоги, без ключей, вопросов, ответов и аудио.
Obsidian использует отдельно выбранную локальную папку; автоматического переноса
прежних SQLite-заметок нет. Её привязка хранится в `obsidian.json` версии 1
в профиле. Перед обновлением сохраните также саму папку заметок.
Резервные копии и личные модели находятся вне установочного каталога и Git.
Не удаляйте профиль при переустановке. Для отката сохраните весь профиль,
восстановите совместимую копию и предыдущий каталог приложения; старый код
не должен открывать новую схему с притворным успехом.

Приватный CUDA-процесс голоса использует проверенные по SHA256 интерпретатор,
конфигурацию, worker, модель и образец. Он получает только текст/темп/язык,
без секретного окружения, файловых команд и сетевого интерфейса. Закрытие
освобождает только его собственный процесс; Ollama и приложения пользователя
не завершаются. Обновление исходников требует обновления соответствующих пинов.

Диагностика без микрофона и динамиков:

```text
desktop_app.py --smoke-test
desktop_app.py --diagnose-voice --extended-models --report PRIVATE_REPORT.json
```

Дополнительная проверка персональной установки должна отдельно загрузить
собранный CT2 CPU-пакет после исключения неиспользуемой cuDNN DLL и проверить
clone manifest уже по установленным путям. Один успешный тест исходников
не заменяет эту проверку. Smart App Control и доверие Windows не меняются;
для этого ноутбука используется независимый подписанный Pythonw с ярлыком.

Полный локальный прогон 4.4.1: **2857 прошли, 4 необязательных проверки symlink
пропущены** за 214,73 секунды, включая изолированный PostgreSQL 18.6, Chrome и Qt.
Дополнительно повторены проверки отмены (реальный Windows loopback без модели),
облачных подставных ответов, утреннего продолжения и Obsidian. Отменённая команда
отбрасывается перед регистрацией распознавания, после декодирования и в очереди
интерфейса; новая команда после остановки остаётся доступна. Реальный платный API,
микрофон, музыка, камера, Windows Hello и физический iPhone этим прогоном не
использовались. Результаты CI и установленной сборки фиксируются отдельно в PR #9.

## Точная приёмка

1. Запустить ярлык; проверить окно, одну копию, трей, автозапуск и полное завершение.
2. Дождаться готовности; произнести имя, короткую команду, русский и английский
   вопрос. Проверить микрофон, шум, собственный голос и предпочтительный тембр на слух.
3. Проверить мгновенный готовый отклик во время подготовки клона, отмену длинной
   речи, последующий запрос и освобождение собственного GPU-процесса при выходе.
4. Остановить Ollama и проверить музыку/задачи/план/таймеры; модель не должна быть
   условием этих функций. Не использовать реальное питание как тест.
5. Сохранить вт/чт/вс без времени, проверить отсутствие среды; перенести один день,
   поставить в очередь уведомление и изменить правило до озвучки — старый текст пропускается.
6. Создать дело на завтра, изменить дату/время, отметить сделано/пропущено/неизвестно;
   перезапустить и убедиться в сохранении и отсутствии выдуманного выполнения.
7. Проверить одно утреннее обращение и одно вечернее в 22:00, паузу/DND и повторный
   запуск. Настоящий вход в Windows и живую акустику проверять отдельно.
8. Проверить наблюдения: только категории, разрывы не засчитываются, браузер
   неизвестен, пауза/очистка работают, резервная копия не содержит наблюдений.
9. Включить/выключить личный контекст: вопрос о плане использует актуальную
   проекцию, общий вопрос её не получает; заметки не отправляются автоматически.
10. Проверить ноль ИИ-запросов на команды; один запрос на свободный вопрос;
    фактические токены или неизвестность, сокращённую историю и отсутствие retry-цепочки.
11. На физическом iPhone настроить личный HTTPS, проверить вход, изменение плана,
    самоотчёт, повтор запроса и отсутствие личного офлайн-кэша. Сейчас это ручная приёмка.
12. При явной настройке внешнего провайдера проверить только свой канал,
    актуальность события, часы и лимит; без настройки статус должен оставаться
    неподключённым. Никакие реальные звонки автоматический тест не делает.
13. В каталоге добавить два проекта с одинаковым именем: голос просит уточнение,
    кнопка открывает выбранный ID. Проверить PyCharm/IDEA, псевдонимы и отзыв корня
    во время проверки редактора. Обновить тестовое EXE: до повторного подтверждения
    оно не открывается. Не проверять произвольные команды оболочки.
14. Включить Hello, проверить системный диалог вручную, заблокировать Windows и
    убедиться, что локальная проверка сброшена. Проверить отсутствие переключателя
    жестов и процесса камеры после запуска и перезапуска.
15. С личным iPhone проверить раздельные ключи и открытие разрешённого проекта;
    запросить рискованное действие и отменить его, дождаться истечения другого.
    Само питание в автоматическом тесте не выполнять. Отозвать разрешение во время
    ожидания, сменить ключ, повторить запрос: дополнительных действий нет.
16. В мобильной вкладке задержать обновление, отключиться и переподключиться:
    старые ответы не показывают данные и не сбрасывают новую сессию. Закрыть Jarvis
    во время принятого запроса: новый доступ прекращается, данные закрываются
    только после окончания уже принятой операции. Проверить отсутствие API/ключей
    в кэше service worker и постоянном хранилище браузера.
17. Задержать первый ответ локальной модели. Пока текста ещё нет, проверить
    «Стоп», новый свободный вопрос и точную команду. Поздние фрагменты и ответы
    отменённого запроса не показываются, не сохраняются и не озвучиваются.
    Отдельно проверить сохранение карточки питания при обычном разговоре и её
    отмену через «Стоп», используя подставной исполнитель.
18. Вручную запросить «Доброе утро»: музыка запрашивается лишь после полной
    записи. Отменить запись новым запросом, отключением речи и «Стоп» — продолжения
    нет. При отсутствии музыкального сеанса не должно быть заявления, что трек играет.
19. В тестовой папке Obsidian создать заметку, найти её и открыть предпросмотр;
    существующий файл не меняется. Проверить старые SQLite-заметки, буквальный HTML,
    отзыв доступа и отмену во время записи, без передачи содержимого ИИ.
20. Без облачных флагов и ключа проверить ноль облачных вызовов. На подставном
    сервере/транспорте проверить отдельные разрешения истории/плана, общий бюджет,
    отказ/таймаут/отмену без повторной отправки и отсутствие фона в STT. Реальную
    отправку в API выполнять только после отдельной настройки; не выдавать наличие
    ключа или локального лимита за подтверждённые кредиты и лимит счёта провайдера.
21. Включить бесплатный режим при синтетическом ключе и всех трёх облачных
    флагах `1`: чат, STT и голос не создают облачный клиент, не читают ключ и не
    записывают резерв расходов. Перезапустить и проверить сохранение режима.
    Во время отложенного ответа включить режим: старый текст/звук не появляются.
    Проверить, что выбранный локальный тембр, темп и выключенный микрофон сохранены.
22. В бесплатном режиме дождаться локального прогрева, задать три свободных
    вопроса, проверить первый фрагмент/полный ответ и нагрузку одновременно с
    локальным голосом. Проверить русскую и английскую фразы, тишину, отмену и
    отказ сервиса; не выдавать синтетические записи за речь владельца.
